# History compaction: summarize the oldest turns behind a token budget

YAAH replays the full persisted history on every turn
(`load_history` -> the model call). Tool results are clipped at write
time, system rows are not replayed, images are pruned, and sub-agent
transcripts stay out of the parent context — but the *text* history
still grows without bound. A long session keeps getting more expensive
per turn and eventually hard-fails at the model's context ceiling.
ZCode-style compaction closes that gap.

## Decisions

**Trigger from measured tokens, not estimates.** The DB already stores
the last call's exact `usage.prompt_tokens` per conversation
(`conversations.context_tokens`, recorded by `set_conversation_usage`
after every model call). Compaction compares that number against the
resolved context window (`get_context_window`: Settings override ->
provider report -> built-in table). No tokenizer is involved, so the
decision is exact and provider-agnostic. When the window is unknown,
the estimate fallback is ~4 chars/token over a conservative default
budget — enough to still protect small local models.

**Budget = fraction of the window, headroom for the reply.** Compaction
fires when measured tokens exceed `context * COMPACTION_TRIGGER_FRACTION`
(default 0.70). The history is compacted down to
`context * COMPACTION_KEEP_FRACTION` (default 0.40), leaving room for
the system prompt, tool plumbing, and a long reply without re-tripping
the trigger every turn.

**Old turns become a prompt-only summary; the recent tail stays verbatim.**
`compaction.py` considers unsummarized transcript messages and sums
chars-per-message from the *cut point* backwards until the keep budget is
met; everything older than that boundary is folded into a bounded summary
generated by a tool-free, non-streaming `model_client.chat` call (the same
provider the session already uses; a user-configured `compaction_model`
override is respected). Repeated compactions summarize the prior prompt
summary together with newly compacted messages. Messages never straddle the
cut: a truncated assistant/tool pair is API-invalid, so the boundary moves
to the last user message.

**The conversation transcript is immutable by compaction.** `compact_conversation`
updates separate prompt-summary and watermark fields on the conversation;
it never deletes, replaces, or edits a message row. Prompt replay injects the
summary and skips transcript rows through the watermark, while transcript
review, export, and history search read the original messages. `context_tokens`
is nulled so the next call re-measures. Database growth is not bounded by
compaction; transcript retention/deletion is a separate user-facing concern.

**History search covers the active conversation.** The read-only
`search_conversation_history` tool uses case-insensitive plain-text matching
over all persisted textual message fields, including tool calls/results and
sub-agent transcript snapshots, plus the prompt summary. Results are capped
and include source metadata and excerpts. It is not available to runs whose
history is disabled.

**Model-call loop keeps appending to the in-memory `messages` after
compaction.** The persisted summary lives in the DB, but the turn's
subsequent calls reuse the already-assembled list; only the next turn
re-loads through `load_history`. Re-running compaction mid-turn is
guarded by a monotonic per-conversation gate (one compaction per turn,
and never twice on the same `context_tokens` value).

**The user is told.** The loop emits a `compacted` event; the UI shows
a collapsible status chip in the active-turn ticker. No compaction
marker is persisted in or added to the conversation transcript.

## Consequences

- Per-call prompt size is now bounded: cost per turn plateaus instead
  of growing linearly, and the provider's context-ceiling 400s stop
  happening on long sessions.
- The full transcript remains available for review and export, and the
  agent can search details that no longer fit in the verbatim prompt tail.
  The model sees the bounded summary plus the most recent ~40% of the
  window verbatim.
- `load_history` repairs and prunes as before, then replays only rows after
  the prompt-summary watermark; compaction remains a separate pass.
  Nothing about short chats changes: compaction is unreachable until
  measured context exceeds 70% of the window.
- The summary call is one extra non-streaming request at the moment of
  compaction. It is deliberately excluded from usage persistence (it
  is not part of the agent's context) and from step counts.
- Legacy conversations compacted by the old implementation remain as-is:
  already-deleted transcript prefixes cannot be reconstructed. A surviving
  legacy system summary is used as prompt context when recognized.
- Scheduled agents with memory enabled get the same protection for
  free on their next fire — their pinned conversations grow the same
  way normal chats do.

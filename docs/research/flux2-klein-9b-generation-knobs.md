# FLUX.2 [klein] 9B: generation knobs and when to turn them

*Research note, 2026-10-15. Primary sources: BFL model card + docs + the official `black-forest-labs/flux2` repo source, the leejet/stable-diffusion.cpp discussion on klein img2img, and YAAH's vendored upstream API doc (`api-upstream.md`). Every claim cites its source; snippet-level evidence is marked as such.*

## Executive summary

FLUX.2 [klein] 9B is **step-distilled to 4 inference steps and guidance-distilled to 1.0** — both values are the model's *designed* operating point, not server defaults. BFL's official implementation declares them **fixed parameters**: its CLI validates and **hard-errors** on any other `num_steps`/`guidance` for the distilled klein variants (flux2 repo, `scripts/cli.py` `validate_model_params` + `FLUX2_MODEL_INFO` in `src/flux2/util.py`). The tunable counterparts are the **undistilled Base variants** (50 steps / guidance 4.0, `fixed_params: {}`). Consequences for knob-picking:

- **`guidance`/`cfg_scale` is not a knob on klein** — it is baked in at 1.0. Exposing it would contradict the model's design (sd.cpp may accept the field, but the model wasn't trained to use it).
- **`steps` beyond 4 is off BFL's warranty, not off the rails.** BFL gives no sanctioned "higher quality" step count for klein, and their reference CLI *refuses* other values — but that guardrail exists in exactly one tool (BFL's own CLI), not in the model and not in sd.cpp, which accepts any count. Empirically, higher step counts visibly change (user report: improve) klein output on sd.cpp (see Evidence note 11). For init-image img2img, sd.cpp's `strength` **truncates the step schedule**, so a low-step distilled model loses proportionally many steps — community guidance there is to *compensate* by raising the configured count (0.5 strength → "6 or so").
- **YAAH's `reference_images` path is NOT init-image img2img**: reference images stay clean and are attended to directly (no strength, no schedule truncation), so poor reference-guided rework at 4 steps is the 4-step schedule's intrinsic detail ceiling — not step starvation — and whether more steps even helps there is an open empirical question.
- The timestep shift (`shifted_timestep`/`flow_shift` in sd.cpp) is computed **automatically** in BFL's implementation from resolution + step count; it is not a recommended user knob.
- For rework quality on klein, the levers with actual evidence are: hires-fix second pass (extra effective diffusion steps), prompt quality (BFL recommends caption upsampling at temperature 0.15 in diffusers), and — if init-image img2img is used — `euler_a` over `euler` plus strength-compensating steps.

## Per-knob detail

### Steps (the knob issue #411 wants)

- The HF model card states klein 9B is a 9B rectified-flow transformer **"step-distilled to 4 inference steps"**, and the official diffusers example uses `guidance_scale=1.0, num_inference_steps=4` (huggingface.co/black-forest-labs/FLUX.2-klein-9B).
- The official repo's model table sets `defaults: {"guidance": 1.0, "num_steps": 4}` and `fixed_params: {"guidance", "num_steps"}` with the comment *"guidance and timestep distilled"* for klein-4b, klein-9b **and** klein-9b-kv; the CLI's `validate_model_params` produces `"Model 'X' requires num_steps=4, but you specified num_steps=N"` and refuses to run (raw.githubusercontent.com/black-forest-labs/flux2/main/scripts/cli.py, src/flux2/util.py).
- Contrast: `flux.2-klein-base-4b/9b` carry `defaults {"guidance": 4.0, "num_steps": 50}`, `fixed_params: {}` — BFL's docs describe Base as "undistilled foundation models with full training signal ... Higher output diversity than distilled models" (docs.bfl.ml/flux_2/flux2_overview). `flux.2-dev` is guidance-distilled (True) but **not** step-distilled (50 steps, unfixed).
- BFL's API docs list klein as "Inference steps 4 (step-distilled)" in both API and open-weight variants; by contrast their `[flex]` model is the one advertised with "Adjustable steps & guidance" (docs.bfl.ml overview comparison table).
- **Img2img interaction**: in sd.cpp, `strength` works on the **init image** (`-i`), which starts denoising from the image plus noise; the schedule is truncated accordingly — the A1111-compat progress endpoint reports "actual sample steps in this pass, after schedule and strength adjustments" (api-upstream.md; leejet discussion #1516). Community guidance for klein: *"--strength will also reduce the number of steps; for a low-step distilled model like Klein, those missing steps may be important. For (say) 0.5 strength, I'd increase the step count to 6 or so."* (leejet discussion #1516, wbruna). This is compensation to restore effective steps, not a claim that more steps = better quality.
- **No official source endorses >4 steps for plain t2i or for reference-guided editing on distilled klein** — BFL's reference CLI rejects other values outright. But that is a warranty guardrail in one tool, not a statement about the model: sd.cpp accepts any count, and a user test on sd.cpp's webui reports a large visible quality difference between 4 and 20 steps (Evidence note 11). Treat >4 steps on sd.cpp as empirically promising, officially unvalidated.

### Steps — user empirical addendum (2026-10-15)

The repo owner reports A/B testing in sd.cpp's webui: 4 vs 20 steps produced a **large visible difference** (20 better) — on both plain renders and img2img-style rework. Consequences:
- On the sd.cpp stack (YAAH's target), >4 steps is not merely unverified; it is user-verified as materially changing output quality for the better.
- The distilled 4-step operating point is an *approximation* of the careful (50-step-style) route; more steps = finer integration. Distillation makes 4 steps fast-and-good-enough, not a hard ceiling.
- Plausible contributor: sd.cpp's 4-step schedule may not be bit-identical to BFL's distilled schedule, so its 4-step output may underperform the canonical quality that longer schedules recover toward. (Unverified; flagged as hypothesis.)
- This revives #411's automatic rework raise as an empirically-motivated heuristic. The clean-reference path needs no truncation compensation, so a floor there rests on this observation plus the finer-integration argument, not on truncation math.

### Guidance / CFG

- Fixed at 1.0 for all distilled klein variants (`fixed_params` includes `guidance`, `guidance_distilled: True` — flux2 util.py). The diffusers pipeline doc explains the semantics: embedded guidance; "Guidance-distilled models approximates true classifier-free guidance for guidance_scale > 1" — i.e. the distilled model already carries its guidance internally (huggingface.co/docs/diffusers/.../flux2).
- dev and klein-base run guidance 4.0 with true CFG enabled. Exposing `cfg_scale`/`guidance.txt_cfg` for klein is contrary to design; sd.cpp's `distilled_guidance` field maps to the embedded-guidance vector and should equally be left alone.

### Timestep shift / flow shift

- In BFL's implementation the schedule is built by `get_schedule(num_steps, image_seq_len)`, where `mu = compute_empirical_mu(...)` depends on the latent sequence length (resolution) and step count, then passed through `generalized_time_snr_shift` — i.e. the shift is **derived, not chosen** (raw flux2 sampling.py). sd.cpp exposes `sample_params.shifted_timestep` / `flow_shift` as overrides (api-upstream.md), but there is no recommendation to touch them; any override would diverge from the official operating point.

### Sampler / scheduler

- Official code uses a flow-matching Euler schedule; sd.cpp default `euler`. The only community signal: for init-image img2img, samplers that re-inject noise each step (`euler_a`) "may work better with -i than the default euler sampler" (leejet #1516). Nothing model-specific for t2i.

### Img2img vs reference editing (the rework distinction)

- stduhpf (sd.cpp contributor), leejet #1516: *"--strength only works for images passed with -i (--init-img), not -r (--ref-image) ... When the initial image is set, instead of starting denoising from pure noise, the model starts off from the initial image with some noise added to it (controlled with the strength parameter). The reference images, on the other hand, stay clean without noise, the model can access them directly to transfer their content to the output."*
- Green-Sky: *"That is not surprising since klein was trained to do that."* — reference-based editing is klein's trained-in rework path; BFL's card likewise markets "text-to-image and image-to-image multi-reference editing in a single unified model" (up to 4 references per the API comparison table).
- Therefore: **reference-guided rework in YAAH (`generate_image reference_images`, #403) runs the full 4-step schedule** — there is no strength truncation to compensate. If those renders disappoint, raising `sample_steps` is a hypothesis to A/B, not an established fix.

### Variants

- klein 9B vs 4B: same operating point (4 steps / guidance 1.0), 9B needs ~29GB VRAM (HF card); 4B is Apache-2.0 and ~13GB (BFL docs). klein 9b-kv adds `use_kv_cache: True` (util.py) — same fixed defaults. **klein-base** variants: 50 steps / guidance 4.0, everything tunable — if a user swaps a base checkpoint onto the same sd.cpp server, the 4-step default becomes badly wrong and a steps knob becomes *essential* rather than cosmetic.

## Implications for YAAH issue #411 (steps knob + ~20-step rework floor)

1. **A raised step count for reference-guided renders is empirically motivated on the sd.cpp stack** (user A/B: 4 vs 20 steps, large visible improvement — Evidence note 11), though it sits outside BFL's validated operating point. Reasonable design: expose `steps` (default = server config), and let an automatic raise apply where the user's own testing supports it — e.g. a modest floor for reference-guided reworks, tuned on this machine rather than assumed from BFL docs. The note should say what ran and why.
2. **Where raised steps ARE defensible: init-image img2img with strength < 1** (truncation compensation). YAAH's `generate_image` currently has no init-image parameter — reference_images is the clean-ref path — so today there is no truncating path to compensate. If #411 wants an automatic assist, the evidence-backed rule is `steps ≥ ceil(default_steps / strength)`-style compensation *if/when* an init-image+strength parameter exists.
3. **`guidance`/`cfg_scale` must NOT be exposed** for klein-class models (distilled-fixed). If the plumbing for other knobs ever lands, sampler choice (`euler_a` for init-img) is the only community-endorsed secondary knob.
4. **Generalization argument survives**: the steps knob remains valuable for base-variant checkpoints (50-step design point) and dev — a 4-step server default would cripple those. Schema guidance: distilled klein-class models — server default unless the caller wants the slower finer-integration render (user-verified improvement on sd.cpp); base/dev-class models — 30–50.
5. **Quality levers for rework that beat step count on the evidence**: the hires second pass (extra effective diffusion), prompt/caption quality (BFL: caption upsampling 0.15), and keeping references within the supported count (≤ 4).
